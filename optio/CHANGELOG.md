# Changelog

## Unreleased

- The settings of a guild are one versioned document, as in the Server. It holds the roles that can ask Optio a question, the text of the guild and of each role for the system prompt, and the tokens in one hour for each role and each member. The migration moves the prompt of each guild into the document. Two changes at the same time both stay.
- `/optioadmin` has the commands `settings view`, `settings update [file]`, `prompt guild`, `prompt role`, `access add`, `access remove`, `limit role`, and `limit user`. They replace `/optioadmin settings`. The query uses only the text of the guild for now.
- Token use: each request to the model writes a row to the new table `query_usage`. The row holds the guild, the user, a hash of the session, the reference of the query, the model, and the four token counts. It also holds the ID of the response message at the provider of the model (`msg_...` of Anthropic). Each day, Optio removes the rows older than `UsageRetentionDays` (default 90). The new metrics are `optio.model.tokens`, by guild and type, and `optio.usage.failures`.

## 0.1.0

The first release. Optio is the service that Custos calls ([ADR 0006](../docs/adr/0006-optio-is-the-service-of-the-contract.md)).

- The discovery document and the Client ID Metadata Document of Custos. The discovery document lists the features in `features_supported`: always `upload`, `stream` while the stream is on, and `query` while the query is on. The default `ServiceName` is `Optio`, the name that Custos shows to the user.
- The upload relay: Optio exchanges the token of Custos for a token of the Server (RFC 8693), and sends the body to the upload API of the Server.
- The producer contract [docs/producers.md](docs/producers.md) and its schema [schemas/event.schema.json](schemas/event.schema.json): a domain service publishes each event with its data and its access policy on NATS JetStream ([ADR 0007](../docs/adr/0007-a-broker-carries-domain-events.md)).
- The stream of `spec/05-stream.md` at `GET /api/v1/stream`, with `stream_endpoint` in the discovery document. Optio makes the stream of the events on NATS JetStream at its start. Each open stream has its own reader on the broker, applies the access policy of each event with the roles of the member from Discord, and first sends its position. Without the broker, a stream request gets `503`, and the upload still works.
- The query of `spec/06-query.md` at `POST /api/v1/query`, with `query_endpoint` in the discovery document. The record of each query is in the NATS bucket `OPTIO_QUERIES`, and its messages go to the stream `OPTIO` below `queries.<guild>.<user>.<client>`. The loop calls the Claude API and the read-only tools of the MCP services, with the card of each service in the prompt. A part of a query has a budget of time and of tool calls. The conversation of a client stays in the bucket `OPTIO_CONVERSATIONS` for the follow-up window. The actions `stop`, the replacement by a new query, the limits of one open query for each user and of queries in each hour, and the close of interrupted queries at the start and the stop.
- Changes: a write tool of a service with `WriteScope` waits for the decision of the user. The states `waiting` and `applying`, the actions `accept` and `refuse`, the expiry of a question after `QuestionSeconds`, the question with the rules of code, the check of each ID of a write call, and `result_unknown` after a failed change. A question continues after a restart.
- The prompt of a guild: the database of Optio (PostgreSQL, `ConnectionStrings:optio`) holds the settings of each guild, and readiness checks it. An administrator sets the prompt with `/optioadmin settings` in Discord. The query puts it last in the system prompt.
- The evaluation set: the test category `Evaluation` examines with the real model whether it selects the correct service and tool for a question. [evaluation/custos.json](evaluation/custos.json) is the set of the Server, and `Optio__EvaluationSet` adds a set of the operator. The example [docs/operator-text.example.txt](docs/operator-text.example.txt). A warning in the log when a service gives a new tool.
- The log of Optio holds the log of the Discord gateway: the connection, a close with its code, for example `4014` without the Server Members Intent, and a reconnection. A gateway request that Discord rate limits gives a warning.
- Telemetry: the metrics `optio.events`, `optio.events.age`, `optio.streams`, `optio.queries`, and `optio.tool.calls`. The service name is `Optio`, unless `OTEL_SERVICE_NAME` sets another.
- The AppHost starts the full system: Keycloak, PostgreSQL, NATS, the Server, and Optio. It reads the realm and the NATS configuration from `deploy/`.
- [deploy/README.md](../deploy/README.md) deploys the full system with Docker Compose, with [deploy/nats/nats.conf](../deploy/nats/nats.conf), `compose.yaml`, and `.env.example`.
